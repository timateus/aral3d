# 7 · Development

## Prerequisites

- Node.js 18+ and npm (or `bun`).
- A modern browser with WebGL 2.

## Setup

```bash
git clone <repo>
cd <repo>
npm install
npm run dev
```

The dev server runs on Vite's default port. Hot module reload covers everything except auto-generated Supabase types.

## Scripts

| Script | Purpose |
|---|---|
| `npm run dev` | Start Vite dev server with HMR. |
| `npm run build` | Production build (Lovable runs this automatically on publish). |
| `npm run build:dev` | Build in development mode (faster, unminified). |
| `npm run preview` | Serve the built bundle locally. |
| `npm run lint` | ESLint over the whole project. |
| `npm run test` | Vitest run-once. |
| `npm run test:watch` | Vitest watch mode. |

## Conventions

- **Design tokens only.** All colors, gradients, and shadows live in `src/index.css` and are themed through shadcn variants. Never hardcode `text-white`, `bg-black`, or `bg-[#hex]` in components.
- **Aesthetic switching** goes through `src/lib/visual-mode.ts` — don't read colors directly from components.
- **UI visibility constraints.** Global UI indicators (timeline, metrics, panels) must stay hidden in every mode except Explore and Walk. See `mem://constraints/ui-visibility`.
- **Don't touch auto-generated files.** `src/integrations/supabase/client.ts`, `src/integrations/supabase/types.ts`, and `.env`'s `VITE_SUPABASE_*` keys are regenerated by Lovable Cloud.
- **State sharing** uses URL search params with debounced `history.replaceState` — keep new state additions in `src/pages/Index.tsx`'s param serializer for shareable links to keep working.

## Adding a new layer

1. Create `src/components/MyLayer.tsx`. Expect props for terrain bounds + the current year if time-sensitive.
2. Cache parsed data in a module-level `WeakMap` or singleton, expose `isMyLayerCached()` for the spinner.
3. Mount inside `<TerrainViewer>` (or as a sibling overlay) gated by a boolean from `Index.tsx`.
4. Add a toggle to the right-side `ControlPanel`.

## Adding a GeoGuessr location

Edit `src/lib/geoguessr-locations.ts`:

```ts
{
  name: "Your Place",
  lat: 43.97240,
  lon: 57.48918,
  zoom: 16,
  hint: "One-sentence hint.",
}
```

Coordinates can be lifted from Google Earth URLs of the form `@lat,lon,...`. Keep titles under ~40 chars so they fit the 360 px panel; the layout wraps long ones via `break-words`.

## Testing

`src/test/example.test.ts` is a placeholder. Add `*.test.ts` next to the code under test. Vitest is configured via `vitest.config.ts` with `jsdom`.

## Memory & plan files

- `.lovable/memory/` — long-lived project knowledge.
- `.lovable/plan.md` — current multi-step plan (Mobile Pass at time of writing).

Memory is read by the AI agent and surfaced as `mem://` references. Treat memory rules as binding (e.g. "Topography MUST omit NaN vertices").
